# 故障排除

本节介绍了在使用 `to-where-cli` 时可能遇到的一些常见问题，并提供了高效的解决方案。了解这些常见情况以及工具如何记录信息有助于您更快地调试问题。

## 常见错误消息

`to-where-cli` 在出现问题时会提供清晰的错误消息。以下是一些常见错误及其解决方法。

### 别名未找到

当您尝试打开、删除或列出配置中不存在的别名时，会发生此错误。

**错误消息示例：**

```
Alias my-alias was not found
```

**原因：**
您提供的别名与 `to-where-cli` 配置中的任何条目都不匹配。

**解决方案：**

1.  **检查拼写错误：** 确保别名拼写正确。
2.  **列出现有别名：** 使用 `tw list` 命令查看所有当前配置的别名。这有助于您确定别名是否存在于不同的拼写下，或者是否从未添加过。有关列出别名的更多详细信息，请参阅[别名管理](./command-reference-alias-management.md)部分。

### 别名已存在

当您尝试添加配置中已有的新别名而未明确请求覆盖它时，会出现此消息。

**错误消息示例：**

```
Alias my-alias already exists, you can use '-f' or '--force' to overwrite it
my-alias => /path/to/existing/location => 5
```

**原因：**
您尝试添加的别名已配置。默认情况下，`to-where-cli` 会阻止意外覆盖，以保护您现有的条目。

**解决方案：**

*   **使用 `--force` 选项：** 如果您打算更新现有别名的地址，请在 `tw add` 命令中使用 `-f` 或 `--force` 标志。这将用新条目覆盖旧条目。
    ```bash
tw add my-alias /new/path/to/location --force
    ```
*   **选择不同的别名：** 如果您想添加一个全新的条目，请选择一个唯一的别名。

### 未强制清空配置

尝试清除整个 `to-where-cli` 配置需要明确确认，这通过使用 `--force` 标志完成。这可以防止意外数据丢失。

**错误消息示例：**

```
To make sure you know what you're doing, you must use '-f' or '--force' to empty
```

**原因：**
您运行了 `tw clean` 命令，但没有使用必要的 `-f` 或 `--force` 标志。

**解决方案：**

*   **添加 `--force` 选项：** 如果您确定要删除所有已配置的别名，请包含 `-f` 或 `--force` 标志。
    ```bash
tw clean --force
    ```

## 配置文件问题

`to-where-cli` 将您所有的别名及其对应的路径存储在一个配置文件中。了解其位置和结构对于故障排除很有用。

**配置文件位置：**

默认情况下，`to-where-cli` 将其配置存储在您主目录中的 YAML 文件中：

*   `~/.tw.config.yml`

**潜在问题：**

*   **文件损坏：** 手动编辑 `.tw.config.yml` 文件可能会引入语法错误，导致工具无法读取或写入其配置。
*   **权限问题：** 不正确的文件权限可能会阻止 `to-where-cli` 访问或修改配置文件。

**解决方案：**

1.  **检查文件：** 在文本编辑器中打开 `~/.tw.config.yml` 以检查是否存在明显的 YAML 语法错误。确保结构有效（例如，正确的缩进，正确的键值对）。
2.  **清空配置：** 如果您怀疑文件已损坏或想重新开始，可以使用 `tw clean --force` 命令。这将重置配置的 `points` 部分，有效地删除所有别名，同时保持文件结构不变。
    *   **注意：** 此操作不可逆，将删除您所有存储的别名。

## 了解日志和输出

`to-where-cli` 使用标准控制台输出提供其操作反馈。这包括信息性消息、成功确认和错误详细信息。

**`to-where-cli` 输出的关键方面：**

*   **信息性消息：** 成功添加或删除别名等操作通常会以 `info` 为前缀显示消息。
    ```
Added successfully
Alias my-alias has been removed
    ```
*   **错误消息：** 如“常见错误消息”部分所示，错误会通过特定消息清晰指示，以指导您。
*   **列出别名输出：** 当您使用 `tw list` 或在 `add`/`delete` 命令后列出别名时，`to-where-cli` 会提供格式化的输出，按访问计数降序排序别名。
    ```
my-alias => /path/to/my/location => 10
another-alias => /another/path => 5
    ```
    在此格式中：
    -   **别名**以蓝色显示。
    -   **地址**（路径）以青色显示。
    -   **访问计数**以绿色显示。

这些日志提供命令执行的即时反馈，是您了解 `to-where-cli` 行为或诊断问题的第一参考点。
